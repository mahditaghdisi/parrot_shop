# 🦜 پرندگان‌شاپ — فروشگاه اینترنتی پرندگان زینتی

فروشگاه اینترنتی کامل، ساخته‌شده با **Django**، برای فروش پرندگان زینتی.

## دیتابیس: فقط SQLite (بدون وابستگی به Postgres رندر)

این پروژه از **SQLite** استفاده می‌کنه — همون رویکردی که برای سایت باباتون (behroozsanat.ir) هم به کار رفت — تا نیازی به دیتابیس مدیریت‌شده و محدود Render (که رایگانش بعد از ۳۰ روز حذف می‌شه و سقف ۱ گیگابایتی داره) نباشه.

### این یعنی چی؟ (مهم — حتماً بخون)

روی Render، دیسک سرور با هر **دیپلوی جدید** (هر بار که کد رو push می‌کنی) از صفر ساخته می‌شه. برای این‌که دیتابیس از بین نره، فایل `db.sqlite3` **داخل گیت commit می‌شه** (برخلاف قبل، دیگه توی `.gitignore` نیست) — یعنی هر دیپلوی، از همون نسخه‌ای از دیتابیس که آخرین بار commit کردی شروع می‌شه.

**نتیجه عملی:**
- سفارش‌ها، حساب‌های کاربری، و تغییراتی که از پنل ادمین می‌دی، تا **دیپلوی بعدی** روی سرور می‌مونن و کار می‌کنن — مشکلی نیست.
- ولی اگه یه تغییر کد جدید push کنی (مثلاً یه باگ رو فیکس کنی) **بدون این‌که دیتابیس زنده‌ی سرور رو قبلش commit کرده باشی**، همه‌ی سفارش‌ها و کاربرهایی که از آخرین commit به بعد اضافه شدن، پاک می‌شن و به نسخه‌ی قدیمی برمی‌گرده.

### روش پشتیبان‌گیری (قبل از هر push جدید انجام بده)

هر وقت می‌خوای کد جدید push کنی و می‌خوای دیتای فعلی سرور (سفارش‌های جدید و غیره) حفظ بشه:

۱. از پنل Render، برو به Web Service → تب **Shell**
۲. محتوای فایل دیتابیس زنده رو ببین که کجاست (معمولاً `/opt/render/project/src/db.sqlite3`)
۳. از طریق تب **Shell** نمی‌شه فایل دانلود کرد، پس ساده‌ترین راه استفاده از یه دستور جنگو برای گرفتن خروجی JSON از داده‌هاست:
   ```bash
   python manage.py dumpdata --natural-foreign --natural-primary -e contenttypes -e auth.permission > backup.json
   ```
   بعد محتوای `backup.json` رو کپی کن (با `cat backup.json`) و روی سیستم خودت ذخیره کن.
۴. روی سیستم خودت، این فایل بکاپ رو لود کن:
   ```cmd
   python manage.py loaddata backup.json
   ```
۵. حالا `db.sqlite3` سیستم خودت به‌روزه — commit و push کن.

> این روش کمی دستیه، ولی چون فروشگاه هنوز در مقیاس کوچیکه (نه صدها سفارش روزانه)، کاملاً قابل مدیریته. اگه در آینده ترافیک بالا رفت و این کار خسته‌کننده شد، می‌تونیم دوباره سراغ یه دیتابیس واقعی (Postgres رایگان روی [Neon](https://neon.tech) یا [Supabase](https://supabase.com) که برخلاف Render، رایگانشون منقضی نمی‌شه) بریم — کد از قبل آماده‌ست که خیلی سریع بشه اون سمت رو هم اضافه کرد.

### درباره تصاویر آپلودی (بدون تغییر نسبت به قبل)

عکس‌هایی که از پنل ادمین آپلود می‌کنی (`media/`) هم مثل قبل روی دیسک موقت Render ذخیره می‌شن و با هر دیپلوی از بین می‌رن — این فایل‌ها بایناری‌ان و commit کردنشون توی گیت عملی نیست. برای الان یا از عکس‌های کوچیک استفاده کن و بعد از هر دیپلوی دوباره آپلودشون کن، یا بعداً یه سرویس ذخیره‌سازی خارجی مثل Cloudflare R2 وصل می‌کنیم.

## اجرای پروژه محلی (CMD ویندوز)

```cmd
cd parrotshop
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_data
python manage.py runserver
```
سایت: `http://127.0.0.1:8000/` — ادمین: `http://127.0.0.1:8000/admin/`

برای دفعات بعد فقط کافیه:
```cmd
cd parrotshop
venv\Scripts\activate
python manage.py runserver
```

## دیپلوی روی Render

۱. مطمئن شو `db.sqlite3` داخل ریپازیتوری commit شده (دیگه gitignore نیست):
   ```cmd
   git add db.sqlite3 -f
   git add .
   git commit -m "switch to sqlite-only, no external db"
   git push
   ```
۲. توی Render Web Service، **دیگه نیازی به متغیر `DATABASE_URL` نیست** — اگه از قبل ست کرده بودی، می‌تونی پاکش کنی (چیزی رو خراب نمی‌کنه، فقط دیگه استفاده نمی‌شه).
۳. بقیه متغیرها (`SECRET_KEY`, `DEBUG=False`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`) دست‌نخورده می‌مونن.
۴. دیتابیس PostgreSQL که قبلاً روی Render ساخته بودی رو می‌تونی از داشبورد حذف کنی تا دیگه هزینه/محدودیتی نداشته باشه.
۵. Save و صبر کن دیپلوی جدید انجام بشه — `build.sh` همون‌طور که قبلاً بود کار می‌کنه (`migrate` روی همون `db.sqlite3` کامیت‌شده اجرا می‌شه، بدون این‌که چیزی پاک کنه).

## دامنه (Cloudflare + ایرنیک)

این بخش تغییری نکرده — همون مراحلی که قبلاً با هم انجام دادیم (رکورد A روی IP رندر برای ریشه دامنه، CNAME برای www، DNS only موقع verify شدن، بعد Proxied برای سرعت بهتر در ایران) دقیقاً همون‌طور معتبره.

## پرداخت آنلاین واقعی (هنوز انجام‌نشده)

هنوز فقط «پرداخت در محل» فعاله. برای وصل کردن واقعی درگاهی مثل زرین‌پال، هر وقت خواستی بگو تا اضافه کنم.
